# PWA Implementation Plan

Stage 1 of the enhancement brief. Goal: after one online visit, the guide installs like an app and every first aid instruction works with no signal. The interface, the 16 topics, the question flow, the CPR beat and the 3D viewer all stay as they are.

## 1. Deployment path

The site is served from `https://nagagamoga-star.github.io/first-aid-quick-guide/`, not from a domain root. Every new path is therefore **relative**:

| Item | Path in page | Resolves to |
|---|---|---|
| Manifest | `manifest.webmanifest` | `/first-aid-quick-guide/manifest.webmanifest` |
| Service worker | `navigator.serviceWorker.register('sw.js')` | `/first-aid-quick-guide/sw.js`, default scope `/first-aid-quick-guide/` |
| `start_url`, `scope` in manifest | `./` | `/first-aid-quick-guide/` (relative to the manifest URL) |
| Fonts, icons, three.js, model | `fonts/…`, `icons/…`, `vendor/three/…`, `models/…` | under `/first-aid-quick-guide/` |

Nothing uses a leading `/`. The tests serve the repo under `/first-aid-quick-guide/` to prove this. Topic URLs (`#cpr`, `#help`) are hashes, so they never reach the server and keep working.

## 2. Manifest (`manifest.webmanifest`)

- `name` "First Aid Quick Guide", `short_name` "First Aid", `lang` "en-AU"
- `start_url` and `scope` `./`, `display` `standalone`
- `theme_color` `#263b48` (Human Atlas slate, same as the top bar), `background_color` `#f3f4f4` (light theme paper)
- Icons: 192 and 512 px PNG, a 512 px maskable PNG, and a 180 px `apple-touch-icon` for iOS, all drawn from `favicon.svg`'s design (slate tile, light cross, teal centre)
- `categories` `["medical", "health"]`

## 4. Service worker design (`sw.js`)

`sw.js` is generated by `src/build.py` from `src/sw.js`. The build inserts the precache list and two version hashes:

- `CORE` cache `fa-core-<hash>`: hash of every precached file's bytes. Any change to the app, fonts or icons produces a new cache.
- `3D` cache `fa-3d-<hash>`: hash of three.js, OrbitControls and the model. App-only updates don't force a 1.2 MB re-download.

| Resource | Strategy | Notes |
|---|---|---|
| Page (`./`, `index.html`, any navigation) | Cache-first from `CORE`, ignoring query strings; network fallback, stored on success | The whole app (CSS, JS, illustrations, content) is inline in this one file, so it can't mix old and new parts |
| Manifest, favicon, icons, fonts | Precached in `CORE` | |
| three.js, OrbitControls, model | Cache-first in `3D`, stored on first use | 3D works offline once it has been opened online. If they aren't cached, the 3D panel says so and the steps carry on |
| Other same-origin files | Network, cache fallback | README, docs |
| Other hosts | Not intercepted | |

### Install, update and recovery

1. **Install**: every precache file is fetched with `cache: 'reload'` (skipping the browser's HTTP cache, so a stale copy can't sneak in) and stored with `cache.addAll`. If any file fails, the whole install fails, the previous version keeps working, and the browser retries on the next visit.
2. **Waiting**: a new version doesn't take over open pages by itself. The page shows a small "A new version is ready. Reload" bar. Tapping it tells the waiting worker to activate, and the page reloads once on `controllerchange`. Closing all tabs also activates it.
3. **Activate**: deletes caches starting with `fa-` that aren't the current `CORE` or `3D` cache, then claims open pages.
4. **Update checks**: the browser checks `sw.js` on navigation (`updateViaCache: 'none'`). The page also calls `registration.update()` on load and when the connection returns.
5. **Self-repair**: if the cache was cleared but the worker is still registered, cache misses fall back to the network and are stored again.

### Why the update is gated

The brief requires that an update never leaves a broken mix of old and new assets. Because the page is one self-contained file, the only versioned unit is `index.html`, and it's swapped as a whole. Clinical corrections reach users when they tap "Reload" or next open the app with no tabs running. For urgent corrections, a later stage could auto-activate when no CPR beat or 3D view is active.

## 5. Offline status and install

- **Offline indicator**: a small "Offline: using the saved copy" label in the top bar when `navigator.onLine` is false, removed when online. It doesn't claim the content is current either way.
- **Saved status**: the footer says "Saved on this device. Works without signal." once the worker controls the page.
- **3D offline**: if 3D hasn't been saved, the panel says the 3D view needs a connection the first time, and that the steps cover everything.
- **Install**: no pop-ups. A quiet "Install app" button appears in the footer only when the browser offers it (Android Chrome, desktop Chrome/Edge). On iPhone and iPad Safari, the footer explains Share then Add to Home Screen. Nothing repeats or interrupts.

## 6. Where the worker does not run

| Host | Service worker | Effect |
|---|---|---|
| GitHub Pages (HTTPS) | Yes | Full PWA |
| `localhost` / `127.0.0.1` | Yes | Testing |
| Claude artifact frame | Blocked by the frame | Registration is wrapped in `try/catch` and skipped; the page works as it does today |
| `file://` | No | Same as today |

## 7. Build changes (`src/build.py`)

- Checks every required source and asset file exists.
- Runs `node --check` on each script (skipped with a warning if Node isn't installed).
- Runs `tests/validate_structure.mjs` (topics, illustrations, flow).
- Generates `index.html` and `sw.js`, then checks there are no leftover markers, every precached file exists, and no `cdn.jsdelivr`/`fonts.googleapis` references remain.
- Prints a short report (sizes, versions, file counts) and exits non-zero on any failure.
- Adds `.nojekyll` so Pages serves files as they are.

## 9. Testing

Automated (`python3 tests/browser_tests.py --pwa`), serving the repo under `/first-aid-quick-guide/`:

- Manifest loads, standalone display, `./` start URL and scope.
- Worker controls the page with scope `/first-aid-quick-guide/`.
- With the network off: page opens, offline label shows, fonts load, search works, all 16 topics and illustrations work, the question flow works, the CPR beat works, a deep link opens in a new tab, a URL with a query string falls back to the cached page, and 3D works after first use.
- Failed 3D load leaves the steps working.
- Interrupted install (one file blocked): the page still works online, and the next visit installs.
- Update: a new version shows the reload bar, activates on tap, and removes the old cache.
- Cleared cache: worker still registered, page still loads online and re-caches.
- Full regression of the Stage 0 checks.

Manual (owner, on devices): install on Android and iPhone, airplane mode, open from home screen, and test on a real update after a commit.
